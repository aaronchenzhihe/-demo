> 主控模组：EC600M-CNLE\
> 摄像头：GC032A（SPI 接口）

## 1. 项目概览

### 1.1 项目介绍

本项目基于 EC600M-CNLE 蜂窝模组与 QuecPython 开发环境，设计一款通过 AI 智能体语音交互控制本地摄像头拍照的智能相机系统。设备通过 4G 网络接入云端，接收来自 AI 智能体的拍照指令，控制本地 GC032A 摄像头完成图像采集与存储，并实现与上层 AI 应用的标准化对接。

项目定位为嵌入式 AIoT 教学案例，旨在帮助学习者掌握摄像头驱动开发、MCP 协议集成思路，以及语音交互与设备控制的完整链路设计。

### 1.2 项目价值

- **技术前沿性**：探索 AI Agent 与物理设备的交互范式，紧跟 MCP 协议应用趋势

- **教学价值**：覆盖摄像头驱动、网络通信、协议集成三大核心技术模块

- **实用价值**：可作为智能监控、远程巡检、AI 视觉应用的前端采集设备

### 1.3 适用平台

| 组件   | 型号/规格               | 功能描述                                  |
| ---- | ------------------- | ------------------------------------- |
| 主控模组 | EC600M-CNLE         | 4G Cat.1 通信、核心逻辑处理，支持摄像头接口            |
| 开发语言 | QuecPython          | 快速原型开发                                |
| 摄像头  | GC032A（SPI 接口）      | 30 万像素，最大分辨率 640×480，与 EC600M-CN 硬件适配 |
| 显示模块 | LCD（ST7789，可选）      | 实时预览画面（需硬件支持），但即使不预览也必须初始化 LCD        |
| 存储   | 模组内部 Flash / SD 卡   | 图像存储                                  |
| 通信方式 | 4G 蜂窝网络 + HTTPS/WebSocket | Gitee 照片备份与小智语音交互                    |

## 2. 核心功能设计

### 2.1 整体架构

系统采用分层设计，核心模块职责如下：

| 层级  | 模块                    | 职责                     |
| --- | --------------------- | ---------------------- |
| 应用层 | `_main.py`            | 指令调度、状态机管理、流程控制        |
| 服务层 | `photo_upload.py`     | Gitee 照片上传                   |
| 服务层 | `camera_srv.py`       | 摄像头操作封装                |
| 驱动层 | QuecPython `camera` 库 | 控制 GC032A 的预览与拍照       |
| 硬件层 | EC600M-CNLE, GC032A   | 物理设备                   |

### 2.2 语音控制闭环

完整的语音控制流程如下：

```
1. 语音指令     用户通过 AI 智能体（如小智 AI）说出"拍照"
2. 指令下发     云端通过 MQTT 下发拍照指令（兼容 MCP 协议格式）
3. 设备执行     EC600M-CNLE 控制 GC032A 摄像头拍照
4. 图像回传     拍照成功后，图像数据上传至云端或本地存储
5. 结果反馈     执行结果通过 MQTT 回传云端
```

### 2.3 状态机设计

| 状态          | 说明                  |
| ----------- | ------------------- |
| `IDLE`      | 待机，监听 MQTT 指令       |
| `CAPTURING` | 执行拍照中，屏蔽新指令         |
| `UPLOADING` | 图像上传中               |
| `ERROR`     | 异常状态（摄像头初始化失败、存储满等） |

状态转换图：

```
         ┌─────────────────────────────────────┐
         │                                     │
         ▼                                     │
    ┌────────┐    MQTT 拍照指令    ┌────────────┐
    │  IDLE  │ ──────────────────► │ CAPTURING  │
    └────────┘                     └─────┬──────┘
         ▲                               │ 拍照完成
         │                               ▼
         │                          ┌────────────┐
         │     上传完成             │ UPLOADING  │
         └─────────────────────────┤            │
                                   └────────────┘
         ▲                               │
         │  ERROR                         │ 上传失败
         │  (初始化失败/存储满)           │
         └───────────────────────────────┘
```

### 2.4 约束与难点

| 问题          | 说明与解决方案                                                                            |
| ----------- | ---------------------------------------------------------------------------------- |
| 摄像头初始化失败    | GC032A 通过 SPI 接口连接，若引脚配置错误或时序不匹配则初始化失败。需检查 SPI 引脚连接正确性，确认摄像头型号为 GC032A             |
| 拍照无回调       | 拍照完成后未触发回调函数，通常因 LCD 未正确初始化。**即使不使用预览功能，也必须初始化 LCD**                               |
| 图像存储空间不足    | 模组内部 Flash 有限（约数 MB），高分辨率 JPEG 图片可能快速耗尽存储。需实现循环存储策略                                |
| MCP 协议集成复杂度 | MCP 协议基于 JSON-RPC，需实现 tools/list 和 tools/call 接口。采用云端 MCP Bridge 方案，设备端只做 MQTT 执行器 |
| 网络传输延迟      | 4G 网络信号差时，MQTT 指令下发延迟增加。拍照过程使用异步回调，不阻塞主循环                                          |
| 实时预览卡顿      | 摄像头预览画面刷新率低（≤15fps），预览为可选功能                                                        |

### 2.5 验收标准 (DoD)

- [ ] 执行 `cam.open()` 返回成功，摄像头进入就绪状态

- [ ] 执行 `cam.start()`，图像文件成功生成并保存，回调函数被正确调用

- [ ] 云端通过 MQTT 下发拍照指令，设备在 3 秒内完成拍照并返回确认消息

- [ ] 拍照成功后，图像数据（Base64 或文件）成功上传至云端指定地址

- [ ] 摄像头未连接或初始化失败时，执行拍照返回错误码，系统不崩溃

- [ ] 连续运行 8 小时，定时执行拍照 100 次，无内存泄漏或死机

## 3. 关键技术要点

### 3.1 摄像头驱动开发

EC600M-CNLE 系列模组硬件上支持摄像头接口，可通过 SPI 连接 GC032A 摄像头。QuecPython 提供 `camera` 库支持拍照与预览功能。

**关键 API（已通过 MCP 验证）：**

```python
from camera import camCapture

# 创建拍照对象（model=0: GC032A, cam_w/cam_h: 摄像头分辨率, lcd_w/lcd_h: LCD 分辨率）
cam = camCapture(0, 640, 480, 1, 240, 240)

# 使能拍照功能
cam.open()

# 注册回调函数
def cam_callback(para):
    if para[0] == 0:
        print("拍照成功，文件:", para[1])
    else:
        print("拍照失败，错误码:", para[0])

cam.callback(cam_callback)

# 执行拍照（自动生成图片文件名，自动添加 .jpeg 后缀）
cam.start(640, 480, "photo")

# 关闭摄像头
cam.close()
```

**注意事项：**

- `camCapture` 构造函数参数：`model`（摄像头型号，0=GC032A）、`cam_w/cam_h`（摄像头分辨率）、`perview_level`（预览等级，EC600M 系列可填 1 或 2）、`lcd_w/lcd_h`（LCD 分辨率）

- 拍照前必须先调用 `cam.open()`

- 拍照结果以回调函数参数为准，`cam.start()` 返回值仅表示"是否开始拍照"

- **LCD 必须初始化**，否则回调不会触发

### 3.2 MCP 协议集成思路

参考已有开源 MCP 摄像头服务器实现，将 MCP 协议适配到 EC600M-CNLE 模组：

**方案一（文档推荐）：设备端集成 MCP Server**

- EC600M-CNLE 作为 MCP Server，通过 HTTP/JSON-RPC 接口接收 LLM 的调用请求

- 需实现 `tools/list` 和 `tools/call` 方法，暴露拍照、状态查询等工具

**方案二（推荐实现）：云端 MCP Bridge**

- 云端部署 MCP Server，将 LLM 调用转换为 MQTT 指令

- EC600M-CNLE 作为执行器，降低设备侧开发复杂度

本项目采用 **方案二（云端 MCP Bridge）**，设备端通过 MQTT 接收指令并执行。

### 3.3 图像数据管理

| 管理策略 | 说明                                              |
| ---- | ----------------------------------------------- |
| 本地存储 | 使用模组 Flash 存储 JPEG 图像，通过 `uos.listdir()` 管理文件列表 |
| 云端上传 | 通过 HTTP/MQTT 将图像 Base64 编码后上传云端                 |
| 存储管理 | 实现循环存储策略（如保留最近 100 张），防止存储耗尽                    |

## 4. 项目文件结构

```
voice_ai_camera/
├── __init__.py              # 包初始化
├── _main.py                 # 入口：初始化全部组件 + 启动 LVGL/相机线程 + 主循环
├── config.py                # 全局配置（GPIO、摄像头、Gitee/百度AI等参数）
├── input.py                 # 按键驱动（GPIO13=选择/快门, GPIO12=确认）
├── logging.py               # 日志分级输出
├── threading.py             # Thread / Lock / Condition / Queue
├── net_manager.py           # 网络管理（驻网、断线重连、信号强度）
├── camera_srv.py            # 摄像头服务层（camCapture 封装 + 循环存储 + 编号命名）
├── photo_upload.py          # Gitee 照片上传（Base64 form-encoded → Gitee API）
├── gitee_manager.py         # Gitee 照片列表查询 / 删除
├── audio.py                 # 音频管理：录音 + Opus 编解码 + TTS 播放 + PA 使能
├── protocol.py              # WebSocket 协议层：小智平台连接 + MCP 工具调用
├── voice_ai.py              # 语音 AI 状态机：录音/识别/TTS/MCP 拍照调度
├── vision.py                # 百度 AI 图像理解（图像上传 + 任务提交 + 结果轮询 + TTS 播报）
├── lvgl_ui.py               # LVGL 界面：主菜单 / 删除照片页 / 图像识别页 / 确认对话框
├── camera_flow.py           # 相机流程：进入/退出拍照模式 + 模式循环（manual/cloud/voice）

test/                        # 独立测试（引用 config.py，无硬编码敏感信息）
```

主菜单功能（GPIO13 选择、GPIO12 确认）：

| 菜单项 | 进入模式 | 说明 |
| ----- | ------- | ---- |
| `Voice AI` | voice | 语音 AI 对话（按 GPIO13 开始/结束录音） |
| `Manual Photo` | manual | GPIO13 作快门手动拍照 |
| `Photo Preview` | - | 浏览本地/Gitee 照片、删除或调用百度 AI 分析 |
| `Interval Photo` | interval | GPIO13 开停定时连拍，照片上传 Gitee |

## 5. 常见坑点

| 问题       | 解决方案                           |
| -------- | ------------------------------ |
| 摄像头初始化失败 | 检查 SPI 引脚连接正确性，确认摄像头型号为 GC032A |
| 拍照无回调    | 确保 LCD 已正确初始化（即使不使用预览功能）       |
| 图像保存失败   | 检查存储空间是否充足，文件名避免重复             |
| 指令响应慢    | 优化主循环调度，拍照过程使用异步回调             |
